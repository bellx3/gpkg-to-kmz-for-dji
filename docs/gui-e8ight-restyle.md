# GUI — E8IGHT 디자인시스템 재구성

CustomTkinter 는 CSS 를 읽지 못하므로 `styles.css` 를 링크할 수 없다. 대신 토큰
(`tokens/colors.css`·`radius.css`·`typography.css`)을 파이썬 상수로 이식하고, 시스템의
**규칙**(헤어라인 보더로 구조를 만든다 · 그림자 없음 · 강조는 시안 하나 · 측정값은 모노스페이스 ·
반경 3/5/8/12 · 컨트롤 높이 26/34/44 · 이모지 없음)을 위젯 생성 지점에 강제한다.

## 체크리스트

- [x] `src/gui/theme.py` — navy 램프·시안 강조·slate 텍스트·상태색·반경·컨트롤 높이·폰트를 토큰으로
- [x] 헤어라인 보더가 계산된 값으로 들어가도록(투명도 대신 navy 위에 합성한 hex — Tk 는 알파를 모른다)
- [x] 위젯 팩토리(`card`·`entry`·`primary`·`quiet`·`ghost`·`option`·`check`·`micro`)로 스타일 호출부 일원화
- [x] `app.py` 의 하드코딩 색·폰트·반경을 팩토리/토큰으로 교체
- [x] 헤더에서 `✈` 이모지 제거 — 이 앱은 사내 도구이므로 브랜드 락업은 넣지 않는다(사용자 판단)
- [x] 안전 판정을 솔리드 버튼 → 상태 배지(틴트 배경 + 상태색 텍스트 + 좌측 상태 레일)
- [x] 측정값(GSD·Blur·스캔 요약·상태)은 모노 + 중점 `·` 구분
- [x] 회귀 확인 — `python -m pytest tests/ -q`

## 판단 기록

- **헤더에 브랜드 락업을 넣지 않는다.** 한 번 `E8`+`IGHT` 타입 조판을 넣었다가 뺐다 — 사용자 요청.
  로고 파일도 없으므로(스킬 규칙: 로고를 임의로 만들지 않는다) 헤더는 제품명만 든다.
- **`set_default_color_theme("dark-blue")` 는 남겼다.** CTk 내장 위젯(스크롤바·세그먼트 버튼 내부)이
  테마 딕셔너리를 참조하므로 통째로 비우면 회귀가 생긴다. 대신 눈에 보이는 위젯은 전부 명시 색으로 덮는다.
- **알파를 쓰지 않는다.** 시스템의 `rgba(154,166,193,.14)` 계열 보더는 각 표면 색 위에 미리 합성해
  hex 로 박았다(`theme.py` 의 `BORDER_*`). Tk 위젯은 투명도를 지원하지 않는다.


## 2차 — 사용성 지적 반영 (2026-08-27)

사용자가 짚은 다섯 가지와 리포트 적용.

- [x] **리포트도 디자인시스템으로** — `src/core/reporter.py` 를 전면 재작성. 다크 네이비 ·
  KPI 타일(좌측 2px 상태 레일) · 36px 행 + 스티키 대문자 헤더 테이블 · 수치 열은 우측 정렬
  모노 tabular · 상태 배지 · 앰버 좌측 레일 고지. 색은 `:root` 커스텀 프로퍼티로만 참조한다.
  단일 HTML 이어야 하므로 CSS 는 인라인이고, 폰트 CDN 이 죽어도 읽히도록 시스템 폴백을 동반한다.
  파일명·메시지는 `html.escape` 로 막았다(외부 데이터가 리포트를 깨거나 주입하지 못하게).
- [x] **입출력 경로 잘림** — 사이드바 330 → 400, 값이 바뀌면 `xview_moveto(1.0)` 으로 **끝**을
  보여준다(긴 경로는 앞이 아니라 뒤가 정보다). 전체 경로는 호버 툴팁(`T.tooltip`).
- [x] **가독성** — 본문 12 → 13px, 모노 11 → 12px, 라벨 색 slate-300 → slate-200,
  컨트롤 높이 28 → 34. 마이크로 라벨도 slate-400 → slate-300 으로 한 단 올렸다
  (11px + slate-400 은 규격대로여도 한국어 UI 에서 읽히지 않았다).
- [x] **지도 로딩** — `src/gui/maptiles.py`. 원인은 네트워크가 아니라 **연결 재사용 부재**였다:
  `tkintermapview` 는 타일마다 `requests.get` 을 새로 열고 25개 스레드가 각자 TLS 핸드셰이크를
  반복한다. 세션 + 커넥션 풀로 갈아 끼우고 받은 타일을 sqlite 에 캐시한다.
  실측(24 타일 · 스레드 8 · Esri Dark · 각 3회 중앙값): **1.56s → 0.08s** (콜드 첫 회 0.55s).
  라이브러리는 포크하지 않고 `map_widget` 이 참조하는 `requests` 심볼만 대체한다 —
  `requests.exceptions` 도 함께 물려줘야 한다(`map_widget.py:540` 이 참조).
- [x] **리포트 열기 버튼** — 로그 패널 구석 → 실행 존, RUN 바로 아래. 리포트는 실행의 결과다.
- [x] **불러오기/저장하기의 정체** — `PRESET` 마이크로 라벨 + 한 줄 설명을 붙였다
  ("위 ①②③ 설정값 묶음입니다. 현장·기체별로 저장해 두고 다음 배치에서 그대로 불러옵니다").

### 판단 기록

- **타일 캐시 실패는 지도를 죽이지 않는다.** sqlite 를 못 열면 `_cache_ok=False` 로 네트워크만
  탄다 — 캐시는 최적화이지 기능이 아니다.
- **HTTP 200 · 비어 있지 않은 응답만 캐시한다.** 오류 페이지나 워터마크 타일을 디스크에 굳히면
  지우기 전까지 계속 그 화면이 나온다.
- 캐시는 `~/.skymission/tilecache.sqlite`, 4만 장 상한(오래된 것부터 정리).

## 4차 — 지도 지연 재조사 (2026-08-27)

세션 재사용으로 네트워크를 없앤 뒤에도 지연이 남는다는 지적. 계측하니 **병목이 옮겨가** 있었다.

계측 도구는 `probe_map2.py`(scratchpad) — 첫 타일 표시 · 큐 비움(화면 완성) · 메인 스레드 점유 ·
요청 타일의 줌/좌표 분포를 잰다.

### 확인된 사실

| 조건 | 첫 타일 | 화면 완성 | 타일 요청 |
|---|---|---|---|
| 콜드 · 선행캐시 반경 8(원본) | 3.29s | 4.14s | 294장 |
| 콜드 · 반경 2 + 1.5s 지연 | 2.37~2.6s | **3.35~3.5s** | 105장 |
| 워밤(디스크 캐시 적중) | 1.00s | **1.30s** | 104장 |

- 네트워크 대기는 워밤에서 **0.00s**, 메인 스레드 점유는 0.1s(회당 0.1ms) — UI 는 막히지 않는다.
- 워밤 1.30s 중 **1.00s 는 앱 구동**(창·위젯 생성)이고 타일은 그 뒤 0.3s 에 다 찬다.
- 남은 콜드 비용은 라이브러리가 첫 화면에 요청하는 **104장(13열×8행, 전부 고유)** 의 네트워크다.
  보이는 타일은 30여 장인데 4배를 요청한다 — `draw_initial_array` 의 타일 범위 계산 때문이다.

### 채택

- [x] 선행 캐시 반경 8 → 2, 시작을 1.5s 늦춘다 (`maptiles.patch_precache`).
      `ImageTk.PhotoImage` 생성이 Tk 락을 잡아 보이는 타일과 경쟁하던 것을 끊는다.
- [x] 동일 URL 동시 요청 합치기(in-flight coalescing) — 같은 바이트를 두 번 받지 않는다.

### 기각 (효과 없음 — 되돌렸다)

- **첫 화면 프리페치**: 앱 구동 1.0s 동안 타일을 미리 받게 했다. 콜드 3.35s → **3.52s** 로
  오히려 나빠졌고 요청만 105 → 170 장으로 늘었다(프리페치 범위가 실제 시야와 어긋나 낭비).
- **최대화를 UI 구성 앞으로**: 타일 범위가 두 번 잡히는 걸 막으려 했으나 요청 수는 104장 그대로,
  첫 타일은 2.65 → 3.00s. (계측 스크립트가 창 크기를 다시 지정해 조건이 오염된 탓도 있다 —
  이 항목은 "효과 없음"보다 "제대로 재지 못했다"에 가깝다.)
- **선행 캐시 반경 0·1**: 2와 차이 없음(3.42/3.37/3.47s). 지연 시작만으로 경쟁이 이미 사라졌다.

### 남은 선택지 (사용자 판단 필요)

첫 화면 104장을 줄이려면 `tkintermapview` 의 `draw_initial_array` / 타일 범위 계산을 패치해야 한다.
라이브러리 내부 좌표 계산에 손대는 일이라 회귀 위험이 있어 하지 않았다.


## 5차 — 입력을 파일 단위로도 (2026-08-27)

폴더 안의 모든 파일을 훑는 것만 가능해 "이 파일만" 이 안 됐다.

- [x] 엔진에 `resolve_input_files(spec, fmt)` · `input_base_dir(spec)` · `INPUT_SEP=';'` 추가.
      폴더 · 파일 하나 · 세미콜론으로 이은 목록을 모두 받는다. 중복은 제거하고, 고른 순서는 지킨다.
- [x] `batch_process_inputs` 의 `missions_dir` 이 세 형태를 다 받는다(인자명은 호환을 위해 유지).
      `out_dir` 기본값도 파일 지정일 때 그 파일의 부모를 기준으로 잡는다.
- [x] CLI `--input-dir` 도 파일·목록을 받는다(도움말 갱신).
- [x] GUI: 입력 행에 **폴더 / 파일** 두 버튼. 파일은 다중 선택(`askopenfilenames`).

      GUI 가 따로 glob 하면 미리보기와 실행이 어긋난다.
- [x] 경로 행을 두 줄(라벨 / 입력+버튼)로 재배치 — 버튼 두 개가 입력칸을 다시 좁혀
      1차에서 고친 "경로 잘림"이 되살아났다. 이제 입력칸이 카드 전체 폭을 쓴다.
- [x] `tests/test_input_spec.py` 8개 — 폴더/단일/다중/포맷 필터 예외/중복 제거/없는 경로/기준 폴더,
      그리고 파일 하나만 지정했을 때 산출물이 하나만 나오는 전 구간 검증.

### 판단 기록

- **직접 고른 파일은 포맷 필터를 통과시킨다.** 포맷 드롭다운이 `gpkg` 인데 사용자가 `.kml` 을
  골랐다면 고른 쪽이 의도다 — 조용히 버리면 "왜 아무것도 안 나오지" 가 된다.
- **엔진에 넘길 때 `Path()` 로 감싸지 않는다** — 세미콜론 목록이 한 경로처럼 뭉개진다.
