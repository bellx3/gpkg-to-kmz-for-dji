## 하네스가 만든 가짜 결함 (기록)

첫 캡처에서 지도가 하얗게 나와 "기본 타일 서버가 죽었다"로 갈 뻔했다. 타일 서버 4종은
전부 정상(200, 0.15~0.55s)이었고, 진범은 **캡처 하네스가 `mainloop()` 대신 `update()`
펌프로 돌던 것** — 그러면 tkintermapview 의 타일 스레드가 `ImageTk.PhotoImage` 를 만들
때마다 `RuntimeError('main thread is not in main loop')` 로 죽어 빈 타일만 남는다(12/12
실증). 하네스를 mainloop + after 로 고치자 지도는 멀쩡했다.

교훈 그대로: **검증 장치가 결함을 만들 수 있다.** 같은 이유로, 앱 본체에서도 메인 루프를
오래 막는 작업(동기 GPKG 파싱 등)이 길어지면 그 사이 타일이 빈 채로 남을 수 있다 —
미리보기 파일 수를 20개로 제한하는 이유이기도 하다.

## 고도화에서 뺀 것 (기각·보류 기록)

- **미리보기의 스레드 분리** — 보류. tkintermapview 가 스레드 안전하지 않아 파싱만
  분리해도 그리기는 메인 루프로 돌아와야 한다. 파일 20개 · 피처 150개 제한으로 체감
  문제가 없어 복잡도를 지불하지 않았다.
- **GPKG 레이어 선택 UI** — 보류. 엔진은 `layer` 인자를 받지만 실무 입력(필지 GPKG)은
  단일 레이어라 수요가 확인되면 넣는다.
- **진행률 %** — 기각. 엔진이 전체 개수를 먼저 세지 않아 분모가 없다. 대신 완료 시
  상태 표시줄 갱신으로 충분.
- **기본 비행 속도 10→15 변경** — 기각. 포트폴리오 카드가 "기본 10"으로 이 도구를
  소개하고 있어 어긋나게 된다. 사용자가 15로 쓰는 것은 프리셋이 담당할 몫.
